# 🌲 숲나들e 수도권 휴양림 빈자리 알림봇

숲나들e([foresttrip.go.kr](https://www.foresttrip.go.kr))에서 **서울·인천·경기 자연휴양림**의
예약 가능한 객실을 **1시간마다** 찾아서 **텔레그램 채널**로 알려주는 봇입니다.

알림에 뜬 객실을 누르면 곧바로 그 휴양림의 그 날짜 예약 화면으로 들어갑니다.
**예약 신청과 결제는 사람이 직접 합니다. 봇은 절대 대신 하지 않습니다.**

## 1. 알림은 이렇게 옵니다

**빈자리가 있을 때** (소리 알림 켜짐 🔔)

> 🌲 **08/12 15:00 수도권 휴양림**
> ✅ 유명산 / 숲속의집 다람쥐 / **8/15~8/17 (2박)** / 4인
> ✅ 산음 / 휴양관 201호 / **8/16 (1박)** / 6인
> (조회 12곳 / 실패 0곳)

**빈자리가 없을 때** (무음으로 조용히 옴 🔕)

> 🌲 **08/12 14:00 수도권 휴양림**
> 예약 가능 객실 없음
> (조회 12곳 / 실패 0곳)

**아침 7시 알림에만** 맨 아래 한 줄이 더 붙습니다. 봇이 살아있다는 표시입니다.

> 🟢 정상 작동 중 (마지막 점검 08/12 07:00)

### 읽는 법

| 표시 | 뜻 |
|---|---|
| `8/15~8/17 (2박)` | 8월 15일에 들어가서 **8월 17일에 나옵니다.** 2박 3일이라는 뜻입니다. |
| `8/16 (1박)` | 8월 16일 하루만 비어 있습니다. |
| `4인` | 그 객실의 인원 수입니다. 사이트가 인원 정보를 안 주면 이 부분은 생략됩니다. |
| `(조회 12곳 / 실패 0곳)` | 12곳을 확인했고 오류는 없었다는 뜻입니다. 실패가 계속 0이 아니면 아래 [문제가 생겼을 때](#10-문제가-생겼을-때)를 보세요. |

- **빈자리가 없어도 매시간 무조건 1건 옵니다.** 알림이 아예 안 오면 봇이 멈춘 것이므로 바로 알 수 있습니다.
- 결과가 30건을 넘으면 상위 30건만 보내고 `… 외 N건`으로 표시합니다.
- 메시지가 텔레그램 한도(4096자)를 넘으면 자동으로 나눠서 보냅니다.
- **정렬 순서**: 박수가 많은 것 → 날짜가 빠른 것 → 휴양림 이름 순입니다. 연박부터 눈에 띄게 하려는 의도입니다.

## 3. 날짜 바꾸는 법

**`config/dates.json` 파일 하나만 고치면 됩니다.** 코드는 건드릴 필요가 없습니다.

> 💡 여기서 말하는 날짜는 전부 **"숙박일(체크인 날짜)"** 입니다.
> 8월 15일에 들어가서 16일에 나오면 숙박일은 **8월 15일**입니다.

### 지금 조회하는 날짜

**(가) 2026년 연휴**

| 연휴 | 숙박일 | 비고 |
|---|---|---|
| 광복절 | 8/14(금) · 8/15(토) · 8/16(일) | 8/17(월) 대체공휴일 |
| 추석 | 9/23(수) · 9/24(목) · 9/25(금) · 9/26(토) | |
| 개천절 | 10/2(금) · 10/3(토) · 10/4(일) | 10/5(월) 대체공휴일 |
| 한글날 | 10/8(목) · 10/9(금) · 10/10(토) | |

**(나) 주말** — 오늘부터 **8주 이내**의 모든 금요일박·토요일박

**(다)** 위 둘을 합치고 중복은 한 번만, **오늘 이전 날짜는 자동으로 빠집니다.**
지나간 연휴를 굳이 지우지 않아도 됩니다.

### 연휴를 추가하려면

`holidays` 안에 이런 덩어리를 하나 더 넣으세요. **쉼표(`,`)를 빠뜨리지 않도록 주의하세요.**

```json
{
  "name": "성탄절",
  "nights": ["2026-12-24", "2026-12-25"]
}
```

### 주말 범위를 바꾸려면

```json
"weekend": {
  "enabled": true,
  "weeks_ahead": 8,      ← 12로 바꾸면 12주 앞까지 봅니다
  "weekdays": [4, 5]     ← 0=월 1=화 2=수 3=목 4=금 5=토 6=일
}
```

- 일요일박도 보고 싶다 → `"weekdays": [4, 5, 6]`
- 주말은 안 보고 연휴만 보고 싶다 → `"enabled": false`

> ⚠️ 날짜는 반드시 `"2026-12-25"` 형식(YYYY-MM-DD)으로 적어주세요.
> 형식이 틀린 줄은 경고만 남기고 건너뛰므로, 조용히 빠져 있으면 형식을 의심해보세요.

## 4. 알림 시간대 바꾸는 법

기본값은 **한국시간 07:00 ~ 23:00, 매시 정각, 하루 17번**입니다.
**새벽 00시~06시에는 조회도 알림도 하지 않습니다.**

### 범위를 좁힐 때 → 파일 1개만

`config/schedule.json`의 숫자만 고치세요.

```json
"start_hour": 9,     ← 오전 9시부터
"end_hour": 22,      ← 밤 10시까지
"heartbeat_hour": 9  ← '정상 작동 중' 줄이 붙는 시각
```

### 범위를 넓힐 때 → 파일 2개

`config/schedule.json`은 **"이 시간에만 보낸다"는 브레이크** 역할이고,
실제로 봇을 깨우는 것은 `.github/workflows/notify.yml`의 `cron`입니다.
**넓히려면 둘 다 고쳐야 합니다.**

`cron`은 세계표준시(UTC) 기준이고 **한국시간 = UTC + 9시간**입니다.

```yaml
- cron: '0 22-23 * * *'   # UTC 22~23시 = KST 07~08시
- cron: '0 0-14 * * *'    # UTC 00~14시 = KST 09~23시
```

예를 들어 새벽 5시부터 보내고 싶다면 (KST 05시 = UTC 20시):

```yaml
- cron: '0 20-23 * * *'   # KST 05~08시
- cron: '0 0-14 * * *'    # KST 09~23시
```

그리고 `config/schedule.json`의 `start_hour`를 `5`로 바꾸면 됩니다.

> ℹ️ GitHub Actions의 예약 실행은 **정각에서 몇 분 늦을 수 있습니다.** GitHub 전체가 붐빌 때
> 밀리는 것으로, 고장이 아닙니다. 메시지에 찍히는 시각은 실제 조회한 시각입니다.

## 5. 지역 추가하는 법

`config/regions.json`의 `regions` 배열에 **한 줄만 추가**하면 됩니다.

```json
"label": "수도권+강원",
"regions": [
  "서울",
  "인천",
  "경기",
  "강원"        ← 이 한 줄 추가 (윗줄 끝에 쉼표 넣는 것 잊지 마세요)
]
```

- `label`은 알림 제목에 나오는 이름입니다(`🌲 08/12 15:00 **수도권** 휴양림`). 안 바꿔도 동작합니다.
- 지역을 바꾸면 봇이 **자동으로 알아채고 휴양림 목록을 다시 수집합니다.**
- 쓸 수 있는 지역 이름:
  `서울` `인천` `경기` `강원` `충북` `충남` `전북` `전남` `경북` `경남` `제주` `대전` `대구` `광주` `울산` `부산` `세종`

> 휴양림이 늘어나면 조회 시간도 늘어납니다. 봇은 서버에 부담을 주지 않으려고 요청 사이에
> 0.5~1초를 쉬므로, 30곳이면 1~2분쯤 걸립니다. 워크플로 제한시간은 10분입니다.

## 7. 봇이 절대 하지 않는 일

이 봇은 **보기만 하는(read-only)** 도구입니다. 아래는 코드에 아예 들어 있지 않습니다.

- ❌ 예약 신청 — 링크까지만 만들어 주고, 누르고 예약하는 건 사람이 합니다
- ❌ 결제
- ❌ 캡차(자동입력 방지) 우회
- ❌ 대기열 우회
- ❌ 로그인 반복 시도 — 실행 1회에 로그인 1번, 세션이 끊겼을 때만 **딱 1번 더**
- ❌ 잦은 조회(aggressive polling)

**서버에 부담을 주지 않기 위한 장치**

| 항목 | 값 | 어디서 바꾸나 |
|---|---|---|
| 조회 주기 | 1시간에 1번 | `.github/workflows/notify.yml`의 cron |
| 동시 요청 | 최대 3개 | `config/endpoints.json` → `http.max_concurrency` |
| 요청 사이 간격 | 0.5 ~ 1초 (무작위) | `http.min_delay_seconds` / `max_delay_seconds` |
| User-Agent | 일반 크롬 브라우저 | `http.user_agent` |

## 8. 사이트 조사 결과 (엔드포인트 명세)

### ⚠️ 먼저 밝혀둘 점

**이 코드를 만든 작업 환경에서는 `www.foresttrip.go.kr`로 나가는 네트워크가
차단되어 있었습니다.** (보안 정책상 외부 사이트 접속이 막힌 환경이었고,
프록시가 해당 도메인에 대해 `403`을 돌려주었습니다.)

그래서 **셀렉터와 엔드포인트를 눈으로 확인하지 못했습니다.** 여기서 두 가지 선택지가 있었습니다.

| 방법 | 문제 |
|---|---|
| ① 그럴듯한 주소를 추측해서 코드에 박아넣기 | 틀리면 봇이 통째로 안 돌아가고, 왜 안 되는지도 알기 어렵습니다 |
| ② **봇이 실행될 때 사이트에서 직접 알아내게 하기** | ✅ 이 방법을 택했습니다 |

**②를 택한 이유**: 추측한 주소를 박아넣는 것보다, 실제로 사이트에 접속할 수 있는
GitHub Actions 안에서 봇이 스스로 관찰해서 알아내는 것이 정확하기 때문입니다.
요청하신 "추측으로 짜지 마라"를 지키는 방법이기도 합니다.

### 봇이 스스로 알아내는 방식 (자동학습)

봇은 실행할 때 이렇게 합니다.

1. Playwright(진짜 크롬)로 로그인합니다.
2. 로그인한 상태로 **실제 예약 화면을 한 번 열어봅니다.**
3. 그 화면이 **어떤 주소로 어떤 JSON을 받아오는지 네트워크를 그대로 엿듣습니다.**
4. 받아온 JSON에서 "객실 목록처럼 생긴 배열"을 점수로 채점해 찾아냅니다.
   (날짜처럼 생긴 값이 있는지, `useDt`·`goodsNm` 같은 키가 있는지 등)
5. 요청에 실려간 값들을 **거꾸로 대조해서** 파라미터 **이름**을 알아냅니다.
   (예: 보낸 값이 `0182`인 칸의 이름이 `insttId`구나)
6. 알아낸 내용을 `config/endpoints.json`에 저장하고, 그 다음부터는 저장된 주소로
   가벼운 HTTP 요청만 씁니다. (브라우저는 실행당 딱 1번만 띄웁니다)
7. 학습 결과는 **7일마다** 다시 확인합니다. 사이트가 개편돼도 일주일 안에 따라갑니다.

관련 코드: `scripts/foresttrip/session.py`의 `discover_monthly()`, `analyse_payload()`, `infer_field_map()`

| 사이트 주소 | `https://www.foresttrip.go.kr` | |
| 휴양림 검색 화면 | `/pot/is/fs/selectFcltSrchView.do` | 요청서에 주신 주소 |
| 휴양림 식별자 | `insttId` (예: `0182`) | 공개된 링크에서 확인 (`…selectFcltSrchView.do?hmpgId=FRIP&menuId=002001&insttId=0182`) |
| 공통 파라미터 | `hmpgId=FRIP`, `menuId=002001` | 위와 같음 |
| 지역 필터 | `srchArea` | 공개된 검색 URL에 함께 나타나는 파라미터 |
| 날짜 파라미터 | `useBgnDtm` / `useEndDtm` (`YYYYMMDD`) | 공개된 검색 URL에 함께 나타나는 파라미터 |
| 페이지 번호 | `nowPage` | 위와 같음 |
| 객실명 필드 | `goodsNm` | 요청서에 명시해주신 필드명 |
| 이용일 필드 | `useDt` | 요청서에 명시해주신 필드명 |
| 로그인 필요 여부 | **필수** | 비로그인 시 401 + 안내 HTML 반환 (요청서 내용) |

### 봇이 알아내야 하는 것 (자동학습 대상)

| 항목 | 상태 |
|---|---|
| 월별예약조회 JSON 주소 | 🔍 실행 시 관찰해서 채웁니다 (`monthly.url`) |
| GET/POST 여부, 파라미터 이름 | 🔍 관찰해서 채웁니다 (`monthly.method`, `monthly.param_names`) |
| JSON 안에서 객실 목록의 위치 | 🔍 관찰해서 채웁니다 (`monthly.rows_path`) |
| 인원수 필드 이름 | 🔍 후보 탐색 (`bassNmpr`, `stdNmpr`, `maxNmpr` …) |
| 잔여수 / 예약가능 여부 필드 | 🔍 후보 탐색 (`rmnCnt`, `rsvbYn` …) |
| 로그인 입력칸 셀렉터 | 후보 여러 개를 순서대로 시도 (`login.id_selectors` 등) |

**첫 실행 뒤 `config/endpoints.json`을 열어보면 실제로 무엇을 찾았는지 다 적혀 있습니다.**
`discovery_note`, `monthly.url`, `field_map._관찰된_키목록`을 보면 됩니다.
자동학습이 실패하면 [9번](#9-엔드포인트-직접-알아내는-법)을 보고 직접 적어주세요.

### 예약 링크(deep link)를 만드는 규칙

알림의 객실을 누르면 열리는 주소는 이 순서로 정해집니다.

1. **`discovered`** — 자동학습이 실제 예약 화면에서 "예약" 링크를 찾아냈다면 그 규칙을 씁니다.
2. **`primary`** (기본값) — 휴양림 + 체크인/체크아웃 날짜까지 붙입니다.
   ```
   https://www.foresttrip.go.kr/pot/is/fs/selectFcltSrchView.do
     ?hmpgId=FRIP&menuId=002001&insttId=0182&useBgnDtm=20260815&useEndDtm=20260817
   ```
   `useBgnDtm`/`useEndDtm`은 공개된 숲나들e 검색 URL에서 `insttId`와 함께 실제로 쓰이는
   파라미터라서, 날짜가 화면에 그대로 반영될 것으로 보고 기본값으로 삼았습니다.
3. **`fallback`** — 위가 안 되면 날짜 없이 휴양림 화면까지만 엽니다.
   이 경우 로그에 `날짜가 붙은 예약 링크를 만들지 못해…` 경고가 남습니다.

**개별 객실(호실)까지 바로 지정하는 링크는 넣지 않았습니다.** 숲나들e의 객실 선택은
날짜를 고른 뒤 화면 안에서 이뤄지는 구조로 보이고, 객실을 URL로 직접 지정하는 규칙을
확인하지 못했기 때문입니다. 자동학습이 그런 링크를 발견하면 `deeplink.discovered`에
자동으로 반영됩니다.

**링크에는 어떤 로그인 정보도 들어 있지 않습니다.** 휴대폰이나 PC 브라우저에 숲나들e
로그인이 되어 있으면 바로 예약 화면이 뜨고, 안 되어 있으면 로그인 화면이 먼저 뜹니다.
👉 **미리 브라우저에 로그인해 두시면 알림을 눌렀을 때 바로 예약 화면으로 들어갑니다.**

### 조회 로직 (요청하신 규칙 그대로)

- `goodsNm`에 **"예비"** 가 들어간 객실은 운영자 보유분이라 **제외**합니다.
- **(휴양림, 날짜, 객실명)** 이 같은 중복 행은 한 번만 셉니다.
- 요청한 날짜 범위 **밖의 `useDt` 행은 버립니다.** (API가 5일치를 함께 주는 경우 대비)
- 같은 (휴양림, 객실)의 빈 날짜를 정렬해 **연속 구간으로 묶습니다.** 하루만 비어도 1박으로 알립니다.
- 응답이 한 달치를 다 안 주면, 빠진 날짜만 **하루씩 따로** 한 번 더 물어봅니다.

## 9. 엔드포인트 직접 알아내는 법

자동학습이 실패해서 `⚠️ 조회 실패: 월별예약조회 엔드포인트를 찾지 못했습니다`가 오면
아래대로 5분이면 직접 알아낼 수 있습니다. **크롬 브라우저**로 하세요.

1. 크롬에서 숲나들e에 **로그인**합니다.
2. 아무 수도권 휴양림의 **월별예약조회 화면**을 엽니다.
3. **F12** 키를 누릅니다. 개발자도구가 열립니다.
4. 위쪽 탭에서 **Network(네트워크)** 를 클릭합니다.
5. 그 아래 필터에서 **Fetch/XHR** 를 클릭합니다.
6. 이제 화면에서 **달을 바꾸거나 조회 버튼을 누릅니다.** 목록에 줄이 새로 생깁니다.
7. 새로 생긴 줄들을 하나씩 눌러 **Response(응답)** 탭을 봅니다.
   `goodsNm`이나 `useDt` 같은 글자가 보이는 줄이 **정답**입니다.
8. 그 줄에서 **Headers(헤더)** 탭을 열고 아래 3가지를 적어둡니다.
   - **Request URL** 중에서 `https://www.foresttrip.go.kr` 뒤쪽 부분 (예: `/rep/or/selectMonthList.do`)
   - **Request Method** (`GET` 또는 `POST`)
   - **Payload(페이로드)** 또는 **Query String Parameters** 에 있는 항목 이름들

9. `config/endpoints.json`의 `monthly` 부분을 이렇게 채웁니다.

```json
"monthly": {
  "url": "/rep/or/selectMonthList.do",      ← 8번에서 적은 주소
  "method": "POST",                          ← GET 또는 POST
  "params": { "hmpgId": "FRIP" },            ← 항상 같은 값으로 가는 항목들
  "param_names": {
    "instt": "insttId",                      ← 휴양림 번호가 담기는 칸 이름
    "date_from": "useBgnDtm",                ← 시작 날짜가 담기는 칸 이름
    "date_to": "useEndDtm",                  ← 끝 날짜가 담기는 칸 이름
    "ym": "srchYm"                           ← 년월(202608)이 담기는 칸 이름
  },
  "rows_path": "data.list"                   ← 응답에서 객실 목록이 들어있는 위치
}
```

- `param_names`에서 **해당하는 칸이 없으면 그 줄은 지우세요.** 예를 들어 년월만 보내고
  날짜 범위는 안 보내는 API라면 `date_from`, `date_to` 줄을 지우면 됩니다.
- `rows_path`는 응답이 `{"data": {"list": [ ... ]}}` 모양이면 `"data.list"`,
  맨 바깥이 바로 배열이면 `null`로 두세요. **모르겠으면 `null`로 두세요. 봇이 알아서 찾습니다.**

10. 저장하고 커밋한 뒤, Actions에서 **Run workflow**로 다시 실행해보세요.

> 💡 **직접 채운 값을 자동학습이 덮어쓰지 않게 하려면** `config/endpoints.json` 맨 위의
> `"auto_discover": true`를 `false`로 바꾸세요.

> 🔧 **자동학습이 무엇을 봤는지 확인만 하고 싶다면** 내 컴퓨터에서 이렇게 해보세요.
> 관찰한 요청들을 점수와 함께 보여줍니다.
> ```bash
> python scripts/discover.py
> ```

## 10. 문제가 생겼을 때

봇은 **어떤 오류가 나도 워크플로를 빨간불로 만들지 않습니다.** 대신 텔레그램으로
`⚠️ 조회 실패: (사유)` 를 보내고 조용히 끝냅니다. 그래서 실패해도 Actions 탭이
빨간 X로 뒤덮이지 않습니다.

| 텔레그램에 온 메시지 | 뜻과 해결법 |
|---|---|
| `⚠️ 조회 실패: 로그인 실패 (…)` | 아이디/비밀번호를 확인하세요. 숲나들e에 직접 로그인해서 비밀번호 변경 요구나 추가 인증이 생기지 않았는지 보세요. Secrets를 다시 등록하면 됩니다. |
| `⚠️ 조회 실패: 월별예약조회 엔드포인트를 찾지 못했습니다` | 사이트가 개편된 경우입니다. [9번](#9-엔드포인트-직접-알아내는-법)대로 직접 채워주세요. |
| `⚠️ 조회 실패: 휴양림 목록을 한 곳도 수집하지 못했습니다` | 검색 화면 구조가 바뀐 경우입니다. `config/forests.json`을 지우고 다시 실행해보세요. |
| `(조회 3곳 / 실패 9곳)` 처럼 실패가 많음 | 사이트가 일시적으로 느리거나 점검 중일 수 있습니다. 다음 시간 알림을 기다려보세요. 계속되면 엔드포인트가 바뀐 것입니다. |
| **알림이 아예 안 옴** | 아래를 순서대로 확인하세요. |

**알림이 아예 안 올 때**

1. Actions 탭에 실행 기록이 있는지 보세요. 없다면 → 3번으로.
2. 실행은 됐는데 알림이 없다면 → 로그에서 `텔레그램 발송에 실패했습니다`를 찾아보세요.
   봇이 채널 **관리자**인지, `TELEGRAM_CHAT_ID`가 맞는지 확인하세요.
3. 실행 기록 자체가 없다면 → GitHub이 스케줄을 꺼버린 것입니다.
   Actions 탭에 `Enable workflow` 버튼이 보이면 눌러주세요.
   (이걸 막으려고 `keepalive.yml`이 매주 월요일에 돌지만, 혹시 모르니 확인하세요.)

**로그 보는 법**: Actions 탭 → 실행 기록 하나 클릭 → `notify` 클릭 → `빈자리 조회 및 알림` 클릭.
아이디·비밀번호·토큰은 `***`로 가려져 있습니다.

### 봇이 스스로 커밋을 남깁니다

- `notify.yml`은 휴양림 목록이나 학습한 주소가 바뀌면
  `chore: 휴양림 목록/엔드포인트 캐시 갱신` 커밋을 남깁니다. (7일에 한 번쯤)

**둘 다 정상입니다.** 캐시를 레포에 저장해 둬야 매시간 사이트를 다시 긁지 않습니다.
커밋이 실패해도 알림 자체에는 영향이 없습니다.

## 12. 제가 임의로 정한 것들

되묻지 말라고 하셔서, 판단이 필요했던 부분은 아래처럼 정했습니다. **마음에 안 드는 게
있으면 말씀해주세요.**

| 정한 것 | 이유 |
|---|---|
| **엔드포인트를 추측해 박지 않고 실행 시 자동학습** | 작업 환경에서 숲나들e 접속이 차단돼 눈으로 확인할 수 없었습니다. 추측한 주소를 박아두면 틀렸을 때 통째로 안 돌아갑니다. ([8번](#8-사이트-조사-결과-엔드포인트-명세) 참고) |
| **예약 링크는 휴양림+날짜까지만, 객실 지정은 안 함** | 객실을 URL로 직접 지정하는 규칙을 확인하지 못했습니다. 자동학습이 찾아내면 자동 반영됩니다. |
| **잔여수 필드를 못 찾으면 "행이 있으면 빈자리"로 간주** | 월별예약조회는 예약 가능한 것만 보여주는 화면이라 이 가정이 안전합니다. 빈자리를 놓치는 것보다 낫습니다. |
| **인원 정보가 없으면 `/ 4인` 부분을 생략** | 없는 정보를 지어내지 않기 위해서입니다. |
| **캐시 파일을 봇이 레포에 커밋** | GitHub Actions는 매번 새 컴퓨터에서 돌아 파일이 사라집니다. 커밋해 둬야 7일 캐시가 의미가 있습니다. |
| **`concurrency` 설정으로 중복 실행 차단** | 실행이 밀려 두 개가 겹치면 알림이 두 번 옵니다. |
| **`regions.json`에 `label` 추가** | 지역을 늘렸을 때 제목이 "수도권"으로 남아 어색해지지 않도록 했습니다. 안 고쳐도 동작합니다. |
| **로그 마스킹을 `print`까지 확장** | 공개 레포라 실수로라도 비밀값이 찍히면 안 됩니다. 표준출력 자체를 감쌌습니다. |
| **keepalive를 월요일 KST 09:17로** | 정각은 GitHub이 붐벼 밀리기 쉬워 애매한 분으로 잡았습니다. |
| **텔레그램 발송 실패 시 재시도 3회** | 일시적인 네트워크 오류로 알림을 놓치지 않기 위해서입니다. |

## 만든 사람을 위한 메모

이 봇은 **공공 예약 시스템을 조회만** 합니다. 예약 신청·결제·캡차 우회·대기열 우회는
구현되어 있지 않고, 앞으로도 넣지 않는 것이 좋습니다. 조회 주기를 1시간보다 짧게
바꾸면 숲나들e 서버에 부담이 되고 차단당할 수 있습니다.
